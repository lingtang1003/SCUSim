# 角色系统（v2.1）· 设计、配置与扩展指南

> 目标：把「54 个匿名随机事件 + 属性结局」升级为「6 名可攻略角色 + 6 条剧情线 + 18 个结局」。
> 全部数据在 `config/*.json`，逻辑在 `src/core/relation.js` / `src/core/storyline.js`，UI 侧只读。
> 红线不变：原生 ESM、无框架无构建、core 不碰 DOM/存储、随机只走 `rng.js`、UI 零 import。

---

## 2. 一局的流程

```
第 1 回合  社团招新（固定）
第 2 回合  迎新晚会（固定）→ 7 个选项：6 个角色 + 「一个人待着」
            选谁 → flags.route_<id> = true、该角色好感 +6，这一局只走这条线
第 3–9    第一步：初遇（必触发）
第 10–19  第二步：升温（好感 ≥ 8 才进得来）
第 20–29  第三步：冲突 / 转折（好感 ≥ 20；有些选择会直接 @break）
第 30–38  第四步：告白 / 收束（好感 ≥ 38；走完 = done，失败 = broken）
第 40 回合 结局判定：主结局 + 副结局（图鉴都解锁）
```

窗口过了没触发 = 错过（`broken`）；好感跌破底线连续 5 回合 = 自动中断。

## 3. 数值设计

### 3.1 好感与阶段

| 好感 | 阶段 id | 显示 |
|---|---|---|
| 0–11 | `stranger` | 陌生 |
| 12–27 | `acquaintance` | 熟识 |
| 28–44 | `friend` | 朋友 |
| 45–59 | `close` | 知己 |
| 60–100 | `lover` | 恋人 |

- 上限 `balance.affinityMax = 100`；阶段由 `characters.json.stages` 的阈值推导，**不写进存档**（改配置后旧档自动重算）。
- 阶段到 `lover` 会把 `player.romance` 同步成 `dating`（兼容 v1 事件里的 `romance` 标记）。

### 3.2 每条线的好感预算

| 线 | 步 1 | 步 2 | 步 3（好/坏） | 步 4 | 最优合计 | 真结局门槛 |
|---|---|---|---|---|---|---|
| 江叙 / 顾迟 / 林予 / 苏晚 | +10 | +12 | +14 / −4 | +18 / +8 | **60** | 55 |
| 周野 / 唐棠 | +10 | +12 | +20 / +10 | — | **48** | 45 |

加上迎新晚会的 +6：最优路线刚好进 `lover` 档；**保守路线**（每步都选第二个选项）通常落在 30–50 之间——
线走完了但没到 55，于是拿到「温暖/遗憾」结局。这就是「好感是门槛、不是数值目标」的设计。

### 3.3 结局（18 条，`priority` 越小越优先）

| 组 | priority | 结局 | 条件 |
|---|---|---|---|
| 角色真结局 | 1–6 | 每名角色 1 条（如「闭庭之后」） | `lineStatus done` + 好感 ≥ 55（配角 45） |
| 温暖 / 遗憾 | 7–12 | 如「没说完的话」 | 好感 ≥ 30（配角 25） |
| 学业 / 生活 | 13–17 | 保研上岸、学术之星、社交名流、小富翁、养生达人 | 绩点 / 属性阈值 |
| 负面 | 18 | 学业警示 | 总绩点 < 2.0（`gpaAtLeast` + `negate`，绕开「永不挂科」决议） |
| 兜底 | 99 | 平凡四年 | `default` |

> `balance.endingPriorityOrder = 'asc'`：角色线结局压过属性结局；同时命中的其余结局记为**副结局**，也进图鉴。

## 4. 配置结构

### 4.1 `config/characters.json`（结构 D / 内容 B）

```json
{
  "id": "linyu", "name": "林予", "gender": "女",
  "role": "文学与新闻学院 · 大二", "college": "literature",
  "title": "校报上没署名的作者", "intro": "校报的摄影兼写手，帽子压得很低。写诗，但不给任何人看。",
  "portrait": { "file": "media/characters/linyu.webp", "silhouette": false },
  "initialAffinity": 0,
  "stages": [
    { "at": 0, "id": "stranger", "name": "陌生" },
    { "at": 12, "id": "acquaintance", "name": "熟识" },
    { "at": 28, "id": "friend", "name": "朋友" },
    { "at": 45, "id": "close", "name": "知己" },
    { "at": 60, "id": "lover", "name": "恋人" }
  ],
  "likedEvents": ["ev_r25"],
  "lineId": "line_linyu"
}
```

### 4.2 `config/storylines.json`

```json
{
  "id": "line_linyu", "charId": "linyu", "name": "林予线", "priority": 1,
  "startIf": { "flag": { "key": "route_linyu", "value": true } },
  "steps": [
    { "id": "meet", "eventId": "ev_r23", "window": [3, 9] },
    { "id": "dinner", "eventId": "ev_r24", "window": [10, 19],
      "gate": { "relationAtLeast": { "charId": "linyu", "value": 8 } },
      "next": { "dinner": "walk", "refuse": "walk" } },
    { "id": "walk", "eventId": "ev_r25", "window": [20, 29],
      "gate": { "relationAtLeast": { "charId": "linyu", "value": 20 } } },
    { "id": "fight", "eventId": "ev_r26", "window": [30, 38],
      "gate": { "relationAtLeast": { "charId": "linyu", "value": 38 } },
      "next": { "makeup": "@done", "breakup": "@break" } }
  ],
  "onBreak": { "affinityBelow": 6, "forTurns": 5 }
}
```

- `next` 的 key 是**本步事件的选项 id**；值是下一步的 `step.id`，或保留字 `@done` / `@break`。
- `gate` 支持 `relationAtLeast` / `flag` / `notFlag` / `college` / `minTurn` / `maxTurn`。
- 一条线的步骤事件必须标 `storylineOnly: true`（不进随机池）、`once: true`、`charId`。

### 4.3 `config/events-characters.json`（内容分片）

19 个角色剧情事件单独放一张表，`loader` 会把它合并进 `config.events`（fixed 在前）。
这样「主表内容」和「角色剧情」可以分开改，减少合并冲突。

事件在原有字段上多了：

```json
{
  "id": "ev_story_jiangxu_1", "charId": "jiangxu", "name": "凌晨的便利店",
  "storylineOnly": true, "once": true, "termRange": [1, 8], "weight": 1,
  "text": "……（回放用的整段摘要）",
  "lines": [
    { "speaker": "旁白", "text": "凌晨一点，宿舍楼下的便利店只剩关东煮还热着。" },
    { "speaker": "江叙", "emotion": "neutral", "text": "……你也这个点出来。" }
  ],
  "options": [
    { "id": "sit", "label": "陪他坐一会儿",
      "resultText": "……", 
      "effects": { "attributes": { "social": 1 }, "relation": { "jiangxu": 10 } } }
  ]
}
```

| 新字段 | 作用 |
|---|---|
| `charId` | 事件绑定角色：UI 右侧出立绘、关系面板计数、权重受好感影响 |
| `lines[]` | 台词分段（`speaker` / `emotion` / `text`）；缺省时退回 `text` 单段 |
| `emotion` | `neutral / smile / sad / shy / surprise`（当前用 CSS 滤镜模拟差分） |
| `storylineOnly` | 不进随机池，只由剧情线状态机强制派发 |
| `once` | 进过 `eventHistory` 后权重归零 |
| `effects.relation` | `{ charId: delta }`，统一走 `relation.changeAffinity` |
| `requires.relationAtLeast` | `{ charId, value }`，不足时选项置灰并显示「需要和 X 更熟」 |
| `layout: "grid"` | 多选项（迎新晚会 7 个）用两列网格，避免撑爆屏幕 |

## 5. 核心模块

| 文件 | 职责 | 关键函数 |
|---|---|---|
| `src/core/relation.js` | 好感 / 阶段 / 列表 / 恋爱同步 | `ensureRelations` `changeAffinity` `stageOf` `listRelations` `syncRomance` |
| `src/core/storyline.js` | 剧情线状态机 | `initStorylines` `ensureStorylines` `dueEvent` `onEventResolved` `checkBreak` `markBroken` `activeLineSummary` |
| `src/core/effects.js` | 统一写入口（新增 relation） | `applyEffects`（`effects.relation`）、`describeChanges`（输出「林予 好感+10」） |
| `src/core/ending.js` | 结局条件（新增 3 类） | `relationAtLeast` / `lineStatus` / `lineDone` |
| `src/core/engine.js` | 接线 | `newGame` 初始化；`enterTurn` 优先级 固定 > 负债 > 剧情线 > 随机；`resolvePendingEvent` 推进线；`buildViewModel` 输出 `relations` / `line` |

状态（随存档走）：

```js
player.relations = { linyu: { affinity: 16, stage: 'acquaintance', met: true, lastTurn: 3 } }
state.storylines  = { line_linyu: { step: 1, status: 'active', since: 3, lastTurn: 3, lowTurns: 0 } }
```

旧存档没有这两个字段也没关系：`buildViewModel` / `newGame` 会幂等补全（`ensureRelations` / `ensureStorylines`）。

## 6. 加一个新角色（8 步）

1. `config/characters.json` 追加一条（`id` 用小写英文/拼音；`stages` 首档 `at` 必须是 0）。
2. 立绘丢进 `media/characters/<id>.webp`（规格见 §7）；暂时没有就 `"portrait": { "file": "", "silhouette": true }`。
3. 在 `config/events-characters.json` 写 3–4 个事件（id 用 `ev_story_<id>_N`），标 `charId` / `storylineOnly` / `once`，
   正文写 `lines`，选项里写 `effects.relation`。
4. `config/storylines.json` 加一条线：4 步、窗口 `[3,9] [10,19] [20,29] [30,38]`、门槛 `8 / 20 / 38`。
5. 迎新晚会（`ev_fixed_welcome`）加一个选项：`effects: { flags: { route_<id>: true }, relation: { <id>: 6 } }`。
6. `config/endings.json` 加两条：真结局（`lineStatus` + `relationAtLeast`），温暖结局（`relationAtLeast 30`），
   并把 priority 插进 1–12 区间（其余结局顺延）。
7. `node tests/verify_characters.mjs` —— G 组会自动遍历角色表，新角色必须也能走到自己的真结局。
8. 更新本文档的阵容表。

> 改完跑 `npm test`（5 套：smoke / verify_ui / verify_audio / verify_settings / verify_characters）。

## 7. 立绘规范

| 项 | 值 |
|---|---|
| 目录 | `media/characters/`（玩家立绘仍在 `assets/char/`，两者分开：一个是「我」，一个是「他们」） |
| 尺寸 | 810×1080（3:4 竖版），WebP，约 70–90 KB |
| 构图 | 头部占上半幅、肩线在 70% 左右；**底部 8% 会被裁掉**（原图水印/边缘） |
| 背景 | 纯色即可（UI 用圆角卡片 + 底部渐隐遮罩，不做透明抠图） |
| 命名 | `<charId>.webp`，角色 id 与 `characters.json` 一致 |
| 表情差分 | 预留：把 `<charId>_<emotion>.webp` 放进来后，在 `lines[].emotion` 处切换即可（当前用 CSS 滤镜模拟） |

## 8. 测试与验收

```bash
npm test                                  # 5 套全绿（smoke / verify_ui / audio / settings / characters）
node tests/verify_characters.mjs          # 角色系统专项：52 项
node server.js                            # 本地看效果：http://localhost:5173
```

`verify_characters.mjs` 覆盖：

- 9 份配置加载与校验、跨表引用、**角色必须是在读学生**、立绘文件存在；
- 新局初始化 relations / storylines；旧存档幂等补全；
- 6 条线各自能走到自己的真结局；保守选择拿温暖结局；冷落断线拿普通结局；谁都不选则没有角色结局；
- 同种子完全可复现；剧情事件不重复触发；
- UI 结构（DOM 桩）：事件里的 NPC 立绘、台词分段与点击推进、选项等待态、好感提示、关系面板 6 张卡。

浏览器里手动验证的入口（dev 专用，不影响正式页面）：`dev/shot.html?scene=event&char=linyu&click=1&dev=1`，
`scene` 可取 `welcome / event / result / relations`。

## 9. 已知边界

- **表情差分**目前是 CSS 滤镜（`smile/sad/shy/surprise`），不是真的差分图；
- 6 名角色都有立绘（统一 810×1080 WebP，63–89 KB）；
- 没有 CG / 语音 / 二周目专属线（属于下一个周期）；
- 一局只走一条线（这是有意的：让每局的选择有分量），想在另一局攻略别人就开新档；
- 好感上限 100，但当前内容能到 60 左右——数值留了余量给后续「约会/礼物」系统。
