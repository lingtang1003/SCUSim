# SCUSim 剧情化优化路线（文游方向）

> 编制依据：静态通读 `src/**`、`config/**`、`docs/CONTRACT.md`（W3 收口版）、`docs/开发方案.md`、`docs/验收/README.md`。
> 本文件不改变现有代码，只给方向、优先级、落点与验收口径；所有建议都遵守现有红线（原生 ESM / 无框架 / 无构建 / 配置驱动 / rng 单入口 / UI 零 import / 静态部署）。
> 验证状态：本次为静态阅读，未在会话内复跑 `npm test`（工作区 PowerShell 被文件权限挡住），文中"现状"均标注了证据文件与行号，可逐条复核。

## 0. 一页结论

**现在是什么**：一个已经能玩通 40 回合的**数值经营 + 事件抽取**模拟器，外面套了一层完成度不错的橙光式视觉小说皮（全屏场景 / 立绘 / 对话框 / 打字机 / 选项条 / 学期结算 / 结局图鉴 / 多存档位）。

**缺什么**：**"故事"还没有接进系统**。选项只改属性，flag 只当开关，结局只看属性阈值。玩家做过的选择不会在结局里回响，遇到的人没有名字、没有好感、没有表情、没有声音。所以它现在是"校园模拟器 + 文游皮肤"，还不是文游。

**终点是什么**：一款可发布的**校园题材剧情驱动文游**——4 名可攻略角色、3 条完整剧情线、12–15 个结局、12 张 CG、15 个成就、一周目 2–3 小时、二周目有新内容、手机可玩、可分享结局卡。

**最该先做的三件事（投入产出比排序）**：

| 顺序 | 做什么 | 为什么是它 | 成本 |
|---|---|---|---|
| 1 | **把结局从"属性阈值"换成"剧情条件"** | 引擎的 `flagEquals / eventDone / all / any / negate` 已经全实现（`src/core/ending.js:52-111`），只差改 `config/endings.json`。改完玩家第一次能感觉到"我的选择被记住了" | 0.5–1 人日，**不动代码** |
| 2 | **给已有恋爱链一个"人"：角色表 + 好感度 + 好感 UI** | `ev_r23–26` 已经是一条完整链（邂逅→聚餐→散步→吵架→和好/分手），但对方是无名"ta"、没有立绘、没有好感数值。同一批文案，加了名字和好感条，体感差 10 倍 | 2–3 周（含 4 个角色 × 8 事件文案） |
| 3 | **演出层：音频 + 表情差分 + 章节卡** | 文游的"氛围"80% 来自声音和节奏，不是文本量。当前 0 音频、0 表情、0 章节感 | 1.5–2 周，可与 2 并行 |

**优先级矩阵（影响 × 成本）**：

```
影响大 ┌───────────────────────────────┐
       │ ② 角色/好感   ① 结局剧情化 ★  │
       │ ④ 剧情线引擎  ③ 音频演出     │
       │ ⑤ 延迟因果链  ⑥ 章节卡/复盘   │
       │ ⑦ CG 图鉴     ⑧ 自动/快进     │
       │ ⑨ 成就/二周目 ⑩ 商城→礼物    │
影响小 └───────────────────────────────┘
         成本高 ←────────────→ 成本低
        ★ = 本周就能做，先做这个
```

**三个投入档位**（人日按"1 人 1 天"计）：

| 档位 | 能达成的形态 | 内容 |
|---|---|---|
| 10 人日 | "像文游了" | 结局剧情化 + 章节卡 + 音频骨架 + 结局复盘 + 给恋爱链一个角色 + 好感条 |
| 25 人日 | "是一条完整的线" | 上述 + 剧情线引擎 + 延迟事件 + 4 角色各 8 事件 + 3 个角色结局 |
| 40+ 人日 | "可发布的文游" | 上述 + CG/成就/二周目/演出打磨 + 12–15 结局 + 移动端 + 模拟器调平衡 |

3. **期末周**：复习 vs 陪她，属性与关系两条线同时承受代价；学期结束弹出小结卡（绩点 / 关系 / 这学期发生的事）。
4. **大四下**：保研、就业、恋爱三条线同时收口，保研资格要求「绩点 ≥ 3.7 且论文 ≥ 80」，而你为了她放弃了竞赛——只有走过的人知道这结局为什么叫这个名字。

### 1.5 不做（明确边界）

- 不做联机 / 排行榜 / 云存档（跨设备仍走 `.scusim` 导入导出；真要云存档再单独立项 Workers + D1）。
- 不做语音配音（成本极高、体积大、和"文字为主"的调性冲突）。
- 不做 3D / 骨骼动画（2D 表情差分 + 转场足够）。
- 不为了文游化引入框架或构建步骤（现有架构完全撑得住，引入反而破坏"静态部署 + 可 Node 测试"的优势）。

## 2. 现状诊断：7 个"文游断层"

### 断层 1 · 选择没有后果：所有结局都是属性阈值

- **证据**：`config/endings.json` 6 条，条件分别是 `attributeAtLeast`（学识/社交/金钱/健康 ≥ 30 或 50）、`warningTrue`、`default`。**没有一条用到 flag**。
- 对比：事件里已经写了 11 个 flag（`club / thesis / debt / romance / crush / crush2 / competition / intern / scholarship / honor / chain_*`），但**没有任何结局读取它们**。
- **影响**：玩家走了"恋爱线"和"竞赛线"，最后结局一模一样；选择只影响属性数字，不影响故事。这是文游最致命的断层。
- **根因**：不是引擎能力不足——`ending.js` 的 `flagEquals / eventDone / all / any / negate` 全部实现——而是**配置没跟上**。
- **修法**：见 §4 P0-1，仅改配置。

### 断层 2 · 没有"人"：没有角色表、没有好感、没有台词、没有表情

- **证据**：`config/` 六张表里没有任何角色数据；`ev_r23–26` 的恋爱对象是匿名"ta"；`ui.js` 只有"玩家立绘"，事件正文全部是旁白（`events.json` 的 `text`），没有 `speaker` 字段。
- **影响**：文游的驱动力是"我想知道她接下来会怎样"，不是"我想把学识刷到 30"。没有人物 = 没有情感投资 = 通关即卸载。
- **修法**：见 §4 P2（characters.json + relations + 好感 UI + 角色事件池）。

### 断层 3 · 事件一次性：没有延迟、没有串联、没有回响

- **证据**：`eventManager.js:50-69` 硬编码了 4 条剧情线的"起始事件"（competition / romance / scholarship / intern），只保证**起始事件**必触发；后续靠 `requires.flag` 随机抽到，**没有步骤推进、没有顺序保证、没有延迟回响**。`state.pendingEvent` 是一个单槽（`engine.js:193-212`）。
- **影响**：玩家选了"拒绝表白"，三周后什么都不会发生——世界没有记住他做过什么。
- **修法**：见 §4 P1-1 / P1-2（storylines.json + 延迟事件队列）。

### 断层 4 · 演出单薄：0 音频、0 表情、0 转场、0 CG、剧情回放只是日志

- **证据**：`assets/` 下有 21 张背景 + 9 张立绘 webp，**没有 `assets/audio/`**；`ui.js` 有打字机（`typeText`）与 reduce-motion，但没有音频、没有表情切换、没有场景转场；"剧情回放"实际是 `showBacklog()` 读 `state.history` 的最后 80 条文本（`ui.js:1710+`）。
- **影响**：同样的文本，有 BGM 和表情差分是"作品"，没有就是"网页"。
- **修法**：见 §4 P0-3 / P0-4 / P3。

### 断层 5 · 节奏重复：40 回合点同一排 6 个按钮

- **证据**：`config/actions.json` 6 个行动固定；`events.json` 随机事件基率 0.45（`balance.json:7`），每个事件只有 2–3 个选项、只改属性。
- **影响**：第 15 回合后玩家已经知道最优解（学习+锻炼循环），"选择"退化成"执行"。
- **修法**：章节卡 + 学期目标（P0-3）、行动变体（P1-5）、剧情线强制节点（P1-1）。

### 断层 6 · 世界数值不咬合：金钱双语义、月度净 0、成长过早见顶

- **证据**：
  - `balance.json:14-15`：`monthlyIncome = monthlyExpense = 2000` → 固定净额 0，经济压力不存在（`economy.js:61-95`）。
  - `balance.walletPerMoneyPoint` 不存在 → `engine.newGame` 里 `perPoint = 0`，玩家"金钱"只有 5 点；但事件里的 money 效果是 −20 / −150 / −300 / +1000 这种货币量级。**同一个字段同时是"点数"和"元"**（Q1 未决）。
  - 考试公式 `score = clamp(60 + 40×√(学识/100) + (健康−60)×0.1, 60, 100)`（`academy.js:99-107`）：学识 0 也拿 60 分，学识 30 拿 82 分，学识 60 拿 91 分——**中前期就基本满绩点**，长线成长没有意义。
  - `failedCourses` 恒 0（永不挂科，D-05 团队决议）⇒ `ending_warning` 0% 可达（D-15 已记录）。
- **影响**：一个没有稀缺、没有风险的校园，是"模拟器"而不是"故事"——文游需要代价。
- **修法**：见 §4 P0-7 / P1-5（钱统一到元 + 月度净额转负 + 用绩点/关系/健康制造风险，而不是删掉"永不挂科"这条已定决议）。

### 断层 7 · 内容工程薄弱：schema 落后、无内容 lint、无平衡模拟器、无迁移

- **证据**：`src/config/schema.js` 仍是 v1，只校验六表结构，不认识 `college`、`eventBias`、`requires`、`ending.condition.type` 白名单、`walletPerMoneyPoint` 等已上线字段；`tests/accept/` 不存在；`state.version` 仍 `1.0.0`；没有跑 1000 局的平衡模拟器。
- **影响**：内容一旦从 54 条涨到 150 条，配置错误只能靠"玩到才炸"；新结局 0% 可达也不会有人发现。
- **修法**：见 §4 P4-4 / P4-5。

## 4. 优化方向（P0 → P4）

> 每项格式：**目标体验 / 做法 / 落点 / 验收 / 成本 / 归属**。
> 归属沿用 `docs/CONTRACT.md §1`：A=引擎与集成，B=经济学业事件，C=UI 与美术，D=配置存储工程测试。

### P0 · 立刻做（1–2 周，低风险高回报，不改架构）

#### P0-1 结局从"属性阈值"改成"剧情条件"

- **目标体验**：玩家走完一条线，结局会准确说出他做了什么。
- **做法**：重写 `config/endings.json`，用已有的 `all / any / flagEquals / eventDone / negate` 组合；`balance.endingPriorityOrder` 切 `'asc'`（越小越优先，符合 SRS 口径，见 D-02）并重排 `priority` 为 1..N。
- **落点**：仅 `config/endings.json` + `config/balance.json`。**零代码改动**。
- **配置草案**（8 条示例，替换现有 6 条）：
  ```json
  { "id": "ending_baoyan", "name": "保研上岸", "priority": 1,
    "condition": { "type": "all", "conditions": [
      { "type": "gpaAtLeast", "value": 3.7 },
      { "type": "flagEquals", "key": "scholarship", "value": "pursuing" },
      { "type": "attributeAtLeast", "key": "knowledge", "value": 60 }
    ] } }
  { "id": "ending_offer", "name": "Offer 到手", "priority": 2,
  ```

## 6. 内容量规划（40 回合节奏表）

单回合约 2–3 分钟（1 事件 + 4 次行动 + 结算），一周目 2–3 小时。建议的事件密度：

| 学期 | 回合 | 主事件（必发） | 剧情线节点 | 随机事件 | 该学期文本 |
|---|---|---|---|---|---|
| 大一上 | 1–5 | 章节卡 + 社团招新 | 林予初遇 | 3–4 | 2500 字 |
| 大一下 | 6–10 | 期末周 | 林予·聚餐 | 3–4 | 2500 字 |
| 大二上 | 11–15 | 学院专属事件（已实现，`eventManager.js:113-117`） | 竞赛线起点 / 林予·散步 | 4–5 | 3000 字 |
| 大二下 | 16–20 | 期末周 | 竞赛组队 | 4–5 | 3000 字 |
| 大三上 | 21–25 | 实习/科研分流 | 竞赛成绩 / 林予·冲突 | 4–5 | 3500 字 |
| 大三下 | 26–30 | 期末周 | 实习内推 / 和好或分手 | 4–5 | 3500 字 |
| 大四上 | 31–35 | 保研/秋招（强制） | 保研申报 / 告白或告别 | 3–4 | 3000 字 |
| 大四下 | 36–40 | 毕业论文（已实现） | 各线收束 | 3–4 | 3000 字 |
| **合计** | 40 | 8 章 | 3 条线 × 4–6 步 | 30–36 | **约 2.4 万字** |

加角色事件池（4 角色 × 8 事件 × 250 字 ≈ 0.8 万字）+ 结局文案（15 条 × 200 字 ≈ 0.3 万字），**总量 3.5 万字左右**，与 §1.4 的目标一致。

**写作排产建议**：先写 1 条完整线（林予线 10 事件 + 3 结局）作为"垂直切片"，跑通后再复制结构到其他角色——不要四线并行写，否则结构一变四条线全返工。

## 9. 红线、风险、与现有决议的冲突

### 9.1 必须继续遵守

- 原生 ES2020 ESM，无框架、无构建、HTTP 运行（`README.md:55-58`）。
- `core/`、`events/` 不碰 DOM / storage；随机唯一入口 `rng.js`；`Math.random` 零容忍（`README.md:28-34`、`CONTRACT.md §7`）。
- UI 零 import、只经 callbacks（新增的 `showChapter / showCg / setBgm` 也必须遵守）。
- 所有数值在 `config/*.json`；新增字段必须同 PR 更新 `CONTRACT.md` + `DATA_DICTIONARY.md` + `schema.js`。
- 资源相对路径（`import.meta.url`），不写死 `localhost`。

### 9.2 与现有决议的冲突提示（需团队拍板，不能静默改）

| 冲突 | 说明 | 建议 |
|---|---|---|
| Q1 金钱语义 | `balance.walletPerMoneyPoint` 缺省 ⇒ 金钱是点数，但事件金额是货币量级 | P0-7 一次定案，同时改结局阈值与 UI 显示 |
| Q8 月度支出 | 配置 2000/2000（净 0）与 SRS 2000/1800 不一致 | 用"净额为负"重新设计（如 1800/1950），并同步修文档 |
| Q6 永不挂科 / D-15 | `ending_warning` 永不触达 | 不改挂科逻辑，改用"绩点 < 2.0"触发学业警示（`gpaAtLeast` + `negate`） |
| D-09 属性初始 | UI 仍默认 5/5/5/5，与"0 起分配 20 点"不一致 | 文游化不阻塞，但建议顺手改掉（1 小时） |

### 9.3 新风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 音频自动播放被浏览器拦 | 首章无声 | 首次 `pointerdown` 解锁 + 顶部提示"点击开启声音" |
| 素材版权 | 无法公开发布 | 只用自制/CC0/已授权素材；`assets/README.md` 记录来源 |
| 内容产能是瓶颈 | 结构做完但没东西可玩 | 先做垂直切片（1 条线），跑通后再量产；用 lint 保证质量 |

| localStorage 体积 | 存档 + 已读表增长 | 已读表只存 id（54→150 条约 2KB）；音频/CG 不缓存 |
| 团队交接 | A/B/C/D 各自改动冲突 | 任何 view/state 增量走 `CONTRACT.md §10` 变更流程 |

## 附录 B · 术语

- **垂直切片**：只做 1 条完整线（含所有系统环节）来验证结构，再量产其他内容。
- **断层**：现有系统与文游体验之间缺失的一环（本文 §2 的 7 条）。
- **flag**：记录玩家历史选择的字符串标记（`state.player.flags`）。
- **剧情线（storyline）**：一组按顺序、带条件与分支的事件，最终指向特定结局。
- **延迟事件**：由某次选择预约、在 N 回合后触发的事件，用来制造"因果感"。
