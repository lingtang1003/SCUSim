## 0. 三分钟读懂

### 0.1 这套分工解决什么问题

四个人的活必须满足三条硬约束，否则"各做各的"一定返工：

1. **文件边界清晰**：每个人只改自己白名单内的文件，跨文件需求走"提 issue → A 裁决"。
2. **契约先行**：所有跨模块的字段名、函数签名、返回结构，先写进 `docs/CONTRACT.md`（A 在 W0 冻结），再动代码。
3. **门禁可验收**：每周每人交"一个可被 A 独立复跑的东西"（一个脚本 + 一个预览 URL + 一份记录），A 不需要读完全部代码也能判通过/退回。

### 2.6 红线（保留 + 新增）

1. 原生 ES2020 ESM、无框架、无打包、HTTP 运行（禁 `file://`）。

## 5. A 的周验收 SOP

### 5.1 验收五步（每人 20 分钟）

**第 1 步 · 看范围（2 分钟）**
- `git diff --stat origin/dev...HEAD`：是否只动白名单文件？
- PR 标题是否带 `[契约变更]`？若带，是否同 PR 改了 `docs/CONTRACT.md`？
- 是否夹带无关改动（整文件格式化、改他人测试）？→ 直接退回。

**第 2 步 · 跑门禁（5 分钟）**

```bash
git fetch origin && git checkout <PR 分支>
node tests/accept/w<N>.mjs        # 本周门禁脚本，必须全 PASS
npm test                          # 全局回归，必须全绿
node tests/unit/<角色>-*.mjs      # 该成员自己的单测
```

**第 3 步 · 抽查红线（3 分钟）**

```bash
grep -rn "Math.random" src/core src/events src/config            # 必须为空
grep -rnE "localStorage|indexedDB|document|window\." src/core src/events   # 必须为空
grep -rnE "(2000|1800|-3000|0\.10|0\.35|warningFailedCourses *= *3)" src/core src/events  # 只允许从 config 读取
```

**第 4 步 · 浏览器手测（8 分钟）**
打开 PR 里的 Cloudflare 预览 URL，按本周 8 项清单点一遍（见 §5.4）。屏幕录制 1 分钟留档。

**第 5 步 · 写记录（2 分钟）**
在 `docs/验收/W<N>-<角色>.md` 按模板填写，PR 评论贴文件链接 + 结论。

## 7. 怎么给 AI 派活（提示词总则）

### 7.1 一次只派一张任务卡

- **不要**把整个项目丢给 AI 说"帮我做完"。按 `docs/分工/<你的角色>.md` 里的任务卡，一次一张。
- 每条新对话先贴"系统提示词"（任务书里有），再贴"本周任务卡"，最后贴需要它看的代码片段或让它自己读文件。
- 让 AI **先输出计划**（要改哪些文件、每个文件改什么、怎么测），你确认后再让它动代码。防止它一口气重写半仓库。

### 7.2 必须要求"真实证据"

- 要求 AI 贴 `node ...` 的真实输出；发现编造（比如"已通过"但没有输出）直接把输出贴回去让它重跑。
- 要求它给出 `文件:行号` 的改动清单，方便你 review。
- 要求它列出"未验证/风险"，这一栏通常最有价值。

### 7.3 防止 AI 越界的三句话

1. "你只能修改以下文件：`…`。修改其他文件前必须先问我。"
2. "不得修改 `docs/CONTRACT.md` 里的接口签名；如必须改，先给出变更理由并等我确认。"
3. "不得删除或改写 `tests/` 下已有的断言来让测试通过。"

### 7.4 上下文怎么带

- 每次新会话，把 `docs/CONTRACT.md` + 你负责文件的现有内容贴进去（或让 AI 自己读路径）。
- 长任务（>1 小时）分两段：先"设计+计划"，再"实现+自测"，中间你 review 计划。
- 会话超过 20 轮就开新的，把"已完成/未完成/下一步"三行摘要带过去。

### 7.5 给 A 的"审 PR 助手"提示词（见 `docs/分工/A-核心引擎与集成.md` §提示词 5）
