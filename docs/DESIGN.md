# SCUSim · DESIGN.md

> 视觉小说（橙光式）界面设计系统。格式对齐 Google Stitch 的 DESIGN.md：
> 纯文本描述设计决策，便于人和 AI Agent 一致地生成/修改界面。
> 对应实现：`css/style.css`（令牌 + 组件）与 `src/ui/ui.js`（结构）。

## 1. Visual Theme & Atmosphere

**一句话**：白纸、红章、黑字 —— 像一本摊开的川大校园手册，被红色印章盖了一下。

- 主情绪是「校园纪实」而不是「奇幻冒险」：画面主体永远是全屏实拍/写实背景，
  界面是压在上面的一层**白纸**，绝不抢画面。
- 红色只出现在**需要被按下/被强调**的地方（主按钮、选中态、名牌、关键数字），
  用一次就要有用一次的理由；页面里红点数量控制在 3~5 处。
- 黑色只承担**阅读**：正文、次要说明、极细分隔线。不用蓝灰，不用彩色中性色。
- 圆角偏大（10–32px）但克制：卡片 14–18px，胶囊 999px，弹窗 24–32px。
- 阴影用**暖黑**（`rgba(20,16,15,α)`），不用蓝调阴影；越靠前的层阴影越大越散。

## 2. Color Palette & Roles

| 角色 | 令牌 | 值 | 用在哪 |
|---|---|---|---|
| 主红 | `--red` | `#b3121a` | 主按钮底、名牌、选中描边、关键数字 |
| 亮红 | `--red-bright` | `#d81b25` | 悬停/按下渐变顶端、事件标签 |
| 深红 | `--red-deep` | `#7d0c12` | 渐变底端、按钮描边、深色文字强调 |
| 红 50/100/200 | `--red-50/100/200` | `#fff2f2 / #ffe0e0 / #ffc4c4` | 选中底、提示底、进度、浅色块 |
| 红透 | `--red-soft` | `rgba(179,18,26,.10)` | 胶囊底、幽灵按钮悬停 |
| 红晕 | `--red-glow` | `rgba(179,18,26,.32)` | 红色元素的投影/焦点环 |
| 白 | `--paper` | `#ffffff` | 面板、卡片、对话框、按钮底 |
| 暖白 | `--paper-2` | `#faf7f6` | 面板渐变底、次级面 |
| 浅灰白 | `--paper-3/4` | `#f3edec / #e9e1e0` | 分隔、输入框描边、禁用底 |
| 墨黑 | `--ink` | `#14100f` | 正文、标题 |
| 中墨 | `--ink-2` | `#4d4543` | 说明、次要信息 |
| 淡墨 | `--ink-3` | `#8f8582` | 占位、时间戳、禁用文字 |
| 发丝线 | `--hair` | `rgba(20,16,15,.12)` | 1px 分隔、卡片描边 |

语义：**涨 = 墨黑，跌 = 红**（`--up` / `--down`）。在红白黑体系里，红色天然代表「损失/危险」，
绿色被刻意排除，避免三色打架。

## 3. Typography Rules

| 层级 | 令牌 | 字号 / 字重 | 用途 |
|---|---|---|---|
| 大标题 | `--t-3xl` | 34 / 700，衬线 | 标题页游戏名 |
| 标题 | `--t-2xl` | 28 / 700 | 弹窗标题、结局名 |
| 小标题 | `--t-xl` | 22 / 600 | 面板小节 |
| 正文 | `--t-base` | 16 / 400 | 对话正文（行高 1.85） |
| 说明 | `--t-sm` | 14 / 400 | 选项数值、卡片副标题 |
| 标签 | `--t-xs` | 12 / 600（字距 .06em） | 印章、步骤、状态胶囊 |

- 字体全部自托管、子集化（`assets/fonts/`，合计约 453 KB）：
  - 主标题 **汉仪铸字木头人 W**（手绘方块感）
  - 副标题 **汉仪铸字儿童乐园 W**（圆润卡通）
  - 正文/UI **汉仪晓波花月圆 W**（`--font`，细笔画、好读，替代系统黑体）
  - **标题字体** **汉仪唐美人 W**（`--font-display`，手写行书）：弹窗标题、表单标题、抽屉标题、
    创建角色大标题、结局名、事件标签，以及徽记 SCUSim（角色信息姓名、创建页表单小标题用正文字体）

  - 第二行的「or」包一层 `.vn-logo__small`：`font-size: .76em` + `vertical-align: .12em`，比中文小一档并略微上抬，夹在「有」和「没问题」之间
- 第二行的「果然」单独包一层 `.vn-logo__tilt`：`font-size: 1.08em`、`translateX(-7px) rotate(5deg)`、`transform-origin: 50% 80%`：
  比后面的「有」略大、整体左移贴住荧光笔色带起点、向右微倾
- 第一行的三段「我的 / 大学 / 四年」之间各留 `0.14em` 间距（`.vn-logo__line-big` 与 `.vn-logo__gap` 的 `margin-left`），「我的」与像素小人的位置不受影响
- 第一行整体右移 14px（`.vn-logo__line:first-child { padding-left: 14px }`），和第二行形成轻微错位，也让「年」更靠近像素小人
- 第一行「我的大学四年」里，**「大学四年」比「我的」大 1.14 倍**（`.vn-logo__line-big`），
  字号差制造节奏，但共用同一基线
- 第一行的「大学」用 `.vn-logo__hl--red`：`color: var(--red)` + 与「有 / 没问题」同款白描边，
  让两个关键词左右呼应
- 标题里的「有 / 没问题」套 `.vn-logo__hl`（「我的大学四年」不带描边）：`-webkit-text-stroke: .055em #fff` + `paint-order: stroke fill`
    + 8 向白色 `text-shadow` 兜底，做出贴纸式白描边
  - **四支字体都只有一个字重（400）**：全站 `font-synthesis: none`，并把这些常用组件显式设为 400，
    否则浏览器会用「合成粗体」把细笔画抹成一团（看起来就像没换字体）
  - 晓波花月圆只有一个「细」字重，官网样张略粗：标题页按钮文字用 `-webkit-text-stroke: .022em currentColor`
    轻微加厚（只描 1/50 em，不会糊），弹窗标题用 `.014em`
  - 缺字按字体栈回落系统字体，不会出现方框
  历史衬线 `--font-display` 只留给装饰性用途。
- 徽记 `SCUSim` 固定用 **汉仪晓波花月圆 W**（`'DisplayHY'`，不随标题位互换），轻微倾斜 -3°
- 红色大标题不描边、不加投影；白字红底时才用 `rgba(255,255,255,.28)` 的内高光。

## 4. Component Stylings

**主按钮 `.btn--primary`**
白字、**纯色 `var(--red)`**（不用渐变，悬停换 `--red-bright`）、内高光、`--red-glow` 投影；
悬停上浮 2px 并加强投影；按下下沉 1px 且内阴影加深 —— 「能按」的手感优先于「好看」。

**选项 `.vn-choice`**（每回合 6 个行动）
白卡 + 1px 发丝描边 + 底部季节浅色；标题前一个红色小菱形（◆）作锚点，
**不使用左侧竖条**（会显得像「列表项」，且与圆角卡片冲突）；
悬停时强调色**从鼠标进入点向外扩散**、把整张卡铺满（液体感）：`::after` 是一块 150% 宽的近圆方块（`border-radius: 47%`），位置由 `--mx/--my` 决定（`ui.js` 只在 `pointerenter` 时写入一次，移动中不更新，避免动画中途「重来」），平时 `transform: translate(-50%,-50%) scale(0)`，悬停 `scale(1.75)`（用 `transform` 而非独立 `scale` 属性，过渡更可靠；起始值用 `scale(0.001)` 而不是 `0`）（**进入 1400ms、离开 480ms**，都是 `cubic-bezier(.4,0,.6,1)`）；**不再自转**（独立 `rotate` 会绕未位移的中心甩动，最后盖不满）；填充用**纯色** `var(--red)`（全站不使用红色渐变）
文字（标题与数值）**同步**在填充爬到一半后转色：进入时 `color 220ms linear`（立即开始，只比填充早），离开时 `color 120ms linear`（立刻回来）；标题与数值共用一个过渡，不会一白一绿；按下微缩；
锁定态灰化、不参与入场动画。

**对话框 `.vn-dialogue__box`**
白纸渐变 + 18px 圆角 + 大而散的暖黑投影；左上角红色名牌（胶囊）压住边框。

**存档卡 `.vn-slot`**
白卡、悬停上浮；空位虚线 + 暖白底；自动存档左侧 3px 红边以示区别。

**图鉴徽章 `.vn-gallery__flag`**
胶囊形；字号 16px、内边距 7×18，已达成用强调色描边+浅底，未达成用淡墨底，
尺寸和列表标题同一视觉量级，缩略图里也能一眼分辨。

**下拉 `.vn-picker`**（学院选择）
原生 `<select>` 的悬停高亮由系统绘制（Windows 是直角灰条），无法加圆角，所以改成自绘：
白底圆角输入框 + 展开列表；列表项 `border-radius: 10px`，悬停为强调色 10% 的圆角色块，
当前项为强调色描边/文字。列表用 `position: fixed` 浮出（面板带 `backdrop-filter`，会成为 fixed 的包含块，
所以先探测原点再摆放）。

**关闭按钮 `.vn-icon--close`**
用两条 `::before/::after` 线（各 13×1.8px，±45°）画 ×，交叉点精确落在圆心；
不再用字符「×」（字符字面重心偏下偏左，视觉上永远差一点）。

**开关 `.vn-switch`**
胶囊；关闭为浅灰白，开启为红渐变 + 内高光 + 红晕投影。

**弹窗 `.vn-modal` / 事件 `.vn-event__card`**
24–32px 圆角、白纸底、`--shadow-3`；入场 260–300ms 缩放淡入。

## 5. Layout Principles

- 4px 基线：`--sp-1..10`（4/8/12/16/20/24/32/40）。
- 标题卡：`min(1120px, 92vw)` 的横版白卡，最小高度 `clamp(330px, 44vh, 500px)`，贴底 34px；网格 `top(徽记+导入存档) / logo / sub / menu`，
  左侧徽记与标题，「导入存档」以纯文字链接**紧挨徽记右侧**（无下划线、无分隔线、gap 14px），右侧 2×2 菜单卡（最小高 96px，标题 24px）
- 主舞台固定四层：**背景 → 立绘 → HUD/选项/对话框**；选项条 2 列 × 3 行，居中偏右（`left: 60%`），宽度 `min(840px, 60vw)`，卡片 `min-height: 96px`、标签 23px、数值 15px，给左侧立绘让位；事件弹层里的选项是单列 `min(560px, 74vw)`，不跟着放大。
- 安全区：底部约 25% 会被对话框盖住，左侧约 30% 立绘常驻。
- 弹窗内容宽度上限约 640px；设置/图鉴类长内容出现滚动而不是压缩。

|---|---|---|
| 0 | 无 | 背景、分隔线 |
| 1 | `--shadow-1` | 选项卡、HUD 胶囊 |
| 2 | `--shadow-2` | 抽屉、弹窗 |
| 3 | `--shadow-3` | 结局卡、事件卡 |
| 红 | `0 8-12px 20-26px var(--red-glow)` | 红底元素（主按钮、名牌、选中） |

## 7. Do's and Don'ts

**Do**
- 红色只标「主操作 / 当前选中 / 关键数字」；
- 面板用白或暖白，靠阴影分层，不靠边框加粗；
- 动效服务于「状态变化」（切换场景、翻开弹窗、按下按钮），时长 200–420ms；
- 所有动效在 `.reduce-motion` 或 `prefers-reduced-motion` 下关闭。

**Don't**
- 不要出现蓝色系（旧皮肤残留一律映射到红/白/黑）；
- 不要用彩色渐变做面板底（只允许白 → 暖白）；
- 不要给红色大写标题加描边/外发光；
- 不要用绿色表示「上涨」—— 涨用墨黑，跌用红；
- 不要在同一个视野里放两种红色块（会互相削弱）。

## 8. Responsive Behavior

| 断点 | 变化 |
|---|---|
| ≥ 1440px | 标题卡 720px 宽；选项条 2 列；立绘 380–510px |
| 880–1439px | 标题卡自适应；选项条仍 2 列，间距收窄 |
| 560–879px | 创建页单栏；立绘缩小；HUD 折行 |
| ≤ 560px | 选项条 88vw 置顶；对话框 96vw；隐藏立绘占位框 |

## 9. Agent Prompt Guide

要改这套界面时，按这个顺序描述需求：

1. **改颜色**：只动 `:root` 里的 `--red*` / `--paper*` / `--ink*`，不要写新的 hex；
2. **改组件质感**：改第 20 节（组件升级）里对应类，不动第 1~18 节的尺寸规则；
3. **改版式**：改 `src/ui/ui.js` 的结构函数（`titleScreen` / `dialogueBox` / `actionChoices`），
   CSS 只做视觉；
4. **加动效**：优先 CSS `@keyframes` + 类名；需要「只在状态变化时播放」时，
   在 `render()` 里比对指纹后挂类（参考 `.vn-stage.is-scene-change`）；
5. 改完必须跑 `node tests/smoke.mjs`、`tests/verify_ui.mjs`、`tests/verify_m1.mjs` 与 `tests/unit/*`。

> 红线：`src/ui/ui.js` 只读 GameState，不碰 DOM 之外的存储/随机数；`css/` 不引外部 CDN 资源（标题字体自托管在 `assets/fonts/`，OFL 授权，见该目录 README）。

---

4. **本身就是强调色的 CTA（「进入下一周」）不要用波浪层**：波浪层也是强调色，铺上去等于没变化。
   这块卡改用「底色提亮 + 上浮 2px + 加重投影」做悬停反馈，并 `::after { display: none }`。

5. **填满时别留浅色描边**：卡片有 `1px solid var(--hair)` 的浅边框，悬停时边框若还是浅色，
   填充退去/填满都会露出一圈白边。做法是悬停时把 `border-color` 设成填充色 `var(--red)`，
   离开时边框用 480ms 慢慢回去，和填充同步。

### 立绘只在局内可换

设置面板按上下文裁剪内容：`lastState` 为空（标题页 / 创建角色）时**不显示「我的立绘」**，标题页那张卡的说明也跟着写成「动效 / 声音」；
进入游戏后（`lastState` 存在）才出现立绘选择，并且只列出与当前角色性别匹配的选项。
`renderTitle()` 里会把 `lastState` 置空，从游戏返回主页后自然收起。

### 设置面板的字体

分组标题与滑块标签（动效 / 声音 / 背景音乐 / 音效 / 我的立绘）统一用标题字体 `var(--font-display)`（汉仪唐美人 W），
与弹窗标题「系统设置」同一支笔触；数值（60%）仍用正文字体，避免数字被写意化。

### 设置的写入是串行的

`saveSettings` 是「读—改—写」，并发调用会互相覆盖：保存设置的同时换立绘，
后者的旧快照会把 `reduceMotion` / 音量写回默认值（表现为「关掉动效保存后又自己打开」）。
修正：storage 里用一条 Promise 队列串行化，并且 UI 侧先 `onSave` 再 `onChangeAppearance`。
回归测试 `tests/verify_settings.mjs`。

### 第二行整行白描边

`.vn-logo__line--accent` 直接带 `-webkit-text-stroke: .048em #fff` + `paint-order: stroke fill`
和 8 向白色 text-shadow，于是「果然 / 有 / or / 没问题 / ！」每个字都有白边；
`.vn-logo__hl` 的那套（.062em）会在这两个词上再叠一层，看起来更厚一点，是有意的节奏差。

### 标题的投影

两行标题都是**深色投影**（`0 4px 12px rgba(20,16,15,.26), 0 1px 2px rgba(20,16,15,.14)`），
白描边单独由 `-webkit-text-stroke` + 8 向白色 text-shadow 负责；
带白描边的字（大学 / 有 / 没问题 / 整行第二行）把投影写在 shadow 列表最后一项，投影落在白边之外。

`.vn-logo__line--accent`（果然有 or 没问题！）的 `text-shadow` 换成白色两层：`0 3px 14px rgba(255,255,255,.5)`；
带白描边的 `.vn-logo__hl` 在同样位置把阴影也替换成白色，描边列表保持 8 向。
第一行（我的 / 大学 / 四年）同样改成白色投影，标题整体不再有灰色硬影。

### 标题的淡投影

主标题两行与副标题都加了一层 `text-shadow: 0 4px 12px rgba(20,16,15,.26), 0 1px 2px rgba(20,16,15,.14)`，
让黑字/红字从白卡上轻轻浮起。带白描边的字（有 / 没问题 / 副标题）把投影写在 shadow 列表**最后一项**，
这样投影落在白描边外圈之下，不会把描边染灰。

### 图鉴条目

结局名 `.vn-gallery__name` 用 20px（说明文字 13–14px），形成「标题—说明」的对比；
卡片 `border-color: transparent`（1px 的 `--hair` 白底上就是一条「分界线」），靠投影分层：
已达成 `0 2px 8px rgba(20,16,15,.08)`、未达成 `0 1px 4px rgba(20,16,15,.05)`；
条目上内边距 8px、行内 `align-items: flex-start`，标题不会在卡里显得偏下；
徽章缩到 `padding: 4px 13px / 13px`，说明的 `margin-top` 只留 2px，两行字靠得更近。
右侧 `已达成 / 未达成` 是胶囊徽章，未达成整卡 `opacity: .6`。

### 存档位

保存 / 读取面板都没有说明句（标题下面直接是槽位），标题分别为「保存进度」「读取进度」；点已有内容的手动存档位时先弹 `showConfirm()`：
标题「保存进度」、正文「是否覆盖当前存档？」，确认后才写盘。自动存档按设计始终直接覆盖，不弹确认。

### 弹层是单层的

`mountOverlay()` 挂新弹窗前会先把旧的那层从 DOM 移除。否则「列表 → 确认 → 列表」这种嵌套流程里，
旧弹窗会残留在下面，关掉最上层后仍看得见一层、点取消也没反应。

### 危险操作的二次确认

「清除存档」不直接执行，先弹 `showConfirm()`：标题「清除存档」、说明
「是否确认清除全部存档？包括现在正在进行的游戏。图鉴中已达成的结局不会消失。」，
按钮为 `确认清除`（主红）/ `取消`（次要）。抽屉底部三个链接去掉了下划线。

### 剩余点数胶囊

`.vn-counter` 默认灰底黑字；`remain > 0` 时加 `.is-ok` 变成红底白字（还有点数没分配 = 需要处理），
`remain === 0` 回到灰色（已完成）。「下一步」按钮在 `remain !== 0` 时禁用并降透明度。
性格标签那一步的「已选 N / 3」同 rules：未选满为红、选满变灰。

### 创建步骤条的三态

| 状态 | 视觉 |
| --- | --- |
| 已填写 `.is-done` | 浅红底（`--red` 11%）+ 深红字 + 红色数字点 |
| 正在填写 `.is-current` | 正红底 + 白字 + 红色投影 |
| 未填写（默认） | 5% 墨色底 + `--ink-3` 灰字 + 灰色数字点 |

### HUD 右侧图标

四个圆形按钮统一用 emoji：💗（关系）/ 💾（保存）/ 📖（剧情回放）/ ☰（菜单），
`font-family` 显式指定 emoji 字族，避免被正文的汉仪字体接管成黑白字形。

emoji 的墨迹重心普遍偏低（📖 最明显，实测偏下 2.7px），用 `padding-bottom` 把字形顶起：
💗/💾 3px、📖 10px、☰ 1px，实测墨迹中心与圆心偏差回到 ±0.4px 以内。
不用 `transform` 是因为 hover 的 `translateY(-1px)` 会把它覆盖掉。

### 事件选项的数量自适应

事件弹层的选项本来就比日常行动多（迎新晚会 7 个），原来沿用 23px 的大字号，一句话要折成两三行。

- `options.length >= 4` 时给容器加 `is-many`：字号 23 → 17px、`min-height` 60px、容器加宽到 `min(860px, 92vw)`，
  7 个选项能一屏铺完；
- **1~3 个选项不加这个类**，保持原样（日常行动、两三个选项的事件观感不变）。

另外事件期间（`.vn-stage.is-event`）会把地图上的「选择今天要去的地方」提示和校区标签藏起来，
避免和事件标题、选项网格叠在一起。

### 对话框与选项互斥

一屏里不会同时出现对话框和选项框，节奏是「先看结果，再选下一步」：

1. 进入地点 / 做完一次行动 → `ui.showDialogue = true`，舞台只渲染对话框（和立绘），**不渲染选项**；
2. 点击对话框（整块可点，右下角有 ▼）：打字机没打完时先补全文字，打完后再点才关闭；
3. 关闭时 `ui.showDialogue = false` 并调 `callbacks.onDialogueDone()`：
   - 行动点还有 → `renderState()` 重绘，选项出现；
   - 行动点已用完 → 直接 `onAdvance()` 进入下一周（回到地图）。

实现要点：`render()` 里是 `ui.showDialogue ? dialogueBox(...) : actionChoices(...)` 的二选一；
`syncDialogue` 只在「换地点 / 新行动 / 事件结算 / 新回合」这四个时机把开关置回 true，
所以关掉之后再重绘不会又把对话框弹出来。

### 行动选项的排版

地点系统上线后，一处地点只有 1~3 个活动，选项面板从「两列三行」改为**单列居中**：

```css
.vn-choices:not(.vn-choices--event) {
  left: 50%; top: auto; bottom: 350px;
  transform: translateX(-50%);
  width: min(520px, 88vw);
  grid-template-columns: 1fr;
}
```

原来的 57%~62% 定位是给六宫格留的，单张卡片会明显偏左；垂直方向用 `bottom: 350px`，
卡片落在画面中下部，不贴着对话框原来的位置；事件选项（`.vn-choices--event`）
有自己的定位规则，用 `:not()` 排除，不受影响。

### 选项卡填充后的白边

`.vn-choice::after` 的波浪填充被 `overflow: hidden` 裁在 **padding box**，而卡片的浅色渐变是按
`border-box` 铺的，于是那 1px 描边下面还是浅色 → 红填充外面出现一圈白边。
修法：`.vn-choice { border-width: 0; background-clip: padding-box; }`（`--gold` 同）。

### 对话框的内侧线

`.vn-dialogue__box::after` 原本是 `inset: 6px` 的一圈细描边（`--red` 12%），在浅色底上像一条多余的线，
现在 `display: none`；对话框只保留背景渐变 + 外投影。

### 弹窗尺寸

`modalShell(title, body, foot, wide)` 的第四个参数：`true` → `--wide`（660px），`'xl'` → `--xl`（780px，系统设置用）。
`.vn-modal__body` 是 `flex: 1 1 auto; min-height: 0; overflow-y: auto; overflow-x: hidden`，
只纵向滚动、页脚常驻；左右内边距 20px，给卡片 22px 的投影留出衰减空间；
滚动条 8px 细条（`scrollbar-width: thin` + webkit 伪元素）。

### 自定义属性不能自引用

`--ink: var(--ink)` 这种写法会让该变量在计算时「循环依赖」而失效，凡是 `color: var(--ink)` 都会变成未定义、
回退到继承色。加减按钮的 +/− 用 `background: var(--ink)` 画线，失效后就是透明的（看不见）。
修正：`--ink: #1a1414`，并删掉皮肤块里的同类自引用。

顺带把 `.vn-step-btn` 的 +/− 改成两条 `::before/::after` 线（12×1.8px，`data-kind="minus"` 隐藏竖线），
不再依赖字形在圆圈里居中。

### 滚动容器里的卡片阴影

`.vn-modal__body` / `.vn-tag-grid` 是 `overflow: auto`，卡片投影会在容器边缘被裁成直线。
做法：给滚动容器加 `padding: 12px 14px` + `margin: -12px -14px` 抵消（视觉位置不变），
并 `overflow-x: hidden` 防止出现横向滚动条；`overflow-y: auto` 会顺带把 `overflow-x` 变成 auto，
所以横向留白必须靠内边距补。滚动容器再加 `scroll-padding: 12px`。

### 选项卡是扁平白卡

`.vn-choice` 平时**没有描边、没有投影**（`border-color: transparent; box-shadow: none`），
只剩白色圆角纸片；投影只在悬停时出现（`0 10px 24px var(--red-glow)`）。
原因：1px 的 `--hair` 边框叠在照片上会形成一圈明显的“界线”，和背景交界很生硬。

### 填充动效的坑（五处）

3. **hover 别再铺整块底色**：旧红白皮肤里 `.vn-choice:hover { background: var(--red) }` 会瞬间把卡片染红，
   盖在 `::after` 波浪层下面，看起来就像「瞬间填满、波浪不见了」。填充只能由 `::after` 一层负责。


1. **起始值别用 `scale(0)`**：个别内核会认为元素“没有尺寸”，直接跳过过渡 → 表现为瞬间填满。
   用 `scale(0.001)`，肉眼同样是零，但过渡一定触发。
2. **关掉「动效」会吃掉过渡**：`.reduce-motion * { transition: none !important }` 是全站规则。
   选项卡填充**不再是例外**（之前为了调试临时开过口子，已移除）：关掉动效后填充立即到位，
   弹窗、抽屉、打字机、季节换色等动效也一并关闭。
## 9.y 地点与行动（地图循环 · 双校区）

每一回合都是「先看地图，再选地点」：

1. **回合开始停在地图**：`player.location = null` 渲染 `.vn-stage--map`——整屏手绘校园地图 + 图钉，
   **没有立绘、没有对话框、地点胶囊也不显示**，只有 HUD 和「选择今天要去的地方」。
2. **两个校区**：`config/locations.json` 的 `campuses` 定义 `江安 / 望江` 两张图
   （`assets/map/jiang-an-map.jpg`、`wangjiang-map.jpg`，均 2560×1440）。
   地图顶部有 `.vn-map__tabs` 切换；默认跟随「人所在的校区」，否则用 `defaultCampus`（江安）。
3. **点图钉前往**（`engine.moveToLocation`）：不消耗行动点；健康 < `requiresHealth` 时拒绝并 toast。
4. **活动按地点过滤**：`locations[].activities` 是 `actions.json` 的 id 子集；
   不在当前地点的行动 → `reason: 'not_here'`；健康 < 3 时只能锻炼/休息。
5. **行动点耗尽 → 自动进入下一周**：`onAction` 后若 `actionPoints <= 0`，toast 并 `setTimeout(1100)`
   调 `onAdvance()`；`advance()` 清空 `location`，于是回到地图。任何新操作都会取消这个定时器。
6. **健康不足去不了**：锁定图钉显示「健康 N」并 toast，不移动。
7. **图钉只显示圆点**：文字胶囊默认 `opacity: 0`，悬停 / 当前地点 / 触屏时才显示，
   这样不会盖住手绘地图上自带的黑字标注（`labelDx/labelDy` 可再微调胶囊位置）。

## 10. 季节配色（游戏内）

**总原则**：**标题页与创建角色永远是红白黑**；进入游戏后，界面强调色跟随当前季节。
实现方式是给 `#app` 打 `data-season="spring|summer|autumn|winter"`，
CSS 只覆盖「强调色阶 + 表面色阶」，所有组件规则继续引用 `var(--red*)` / `var(--paper*)`，
因此选项、菜单、弹窗、名牌、进度条、HUD 会一起换色，不需要逐组件改。

季节来自游戏内既有的回合 → 季节映射（`SEASON_CYCLE`，一个学年 10 回合）：
秋 · 秋 · 秋 · 冬 · 冬 · 冬 · 春 · 春 · 春 · 夏。

| 季节 | 主题键 | 色板（直接取自参考图） | 强调底上的字 |
|---|---|---|---|
| 春 | `spring` | 底 `#f2fff2` · 强调 `#a7d3a2` · 奶油 `#ffecc5` · 樱花粉 `#fed4d8` | 深墨绿 `#22301f` |
| 夏 | `summer` | 底 `#f0fff4` · 强调 `#19c7d7` · 柠檬 `#d9ff9c` · 天空 `#aee8ff` | 深青 `#03333a` |
| 秋 | `autumn` | 赭红 `#aa333c` · 浅橙 `#fbd3ac` · 橄榄 `#9aab64` · 苔绿 `#3c5227` | 白 `#ffffff` |
| 冬 | `winter` | 旧铜 `#775537` · 奶油黄 `#fbe29d` · 雾青 `#c0ddda` · 贝壳白 `#f1f1f1` | 奶油黄 `#fbe29d` |

规则：
- **文字也跟着季节走**：`--ink/--ink-2/--ink-3` 由当季色卡派生——春秋用色卡色的深阶，秋直接用深苔绿 `#3c5227`，冬直接用旧铜 `#775537`；浅色（鼠尾草绿/汽水青）用 `color-mix` 压深到可读；
- 每个季节同时给出 50/100/200 浅色阶，用于选中底、提示底、选项卡底部渐变；
- 文字色只在季节色相内做深浅（`--up` 跟着季节走），不引入第二种彩色；
- 换季时 `background / border-color / color / box-shadow` 走 320ms 过渡，避免硬切；
- 无障碍与减弱动效不受影响（只换颜色，不换动画）。
