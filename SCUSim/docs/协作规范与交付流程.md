## 2. 开发流程总览（阶段 + 集成检查点）

```
阶段0 契约冻结 ──G1──▶ 阶段1 模块并行 ──G2(每模块)──▶ 阶段2 端到端集成 ──G3──▶ 阶段3 测试与交付 ──G4──▶ 交付
```

- **阶段0 契约冻结**（已完成）：数据字典 + 统一接口 + 架构决策 + 工程/配置骨架。
- **阶段1 模块并行**：A 写 rng/state/engine/ending；B 写 economy/academy/eventManager + 配置数值；C 写 ui；D 写 loader/storage/schema/测试。
- **阶段2 端到端集成**：main 接通 engine+storage+ui，存档/图鉴/导入导出打通。
- **阶段3 测试与交付**：冒烟 + 浏览器手测 + Cloudflare Pages 部署。

**四个集成检查点（Gate）**

| Gate | 进入条件 | 把关人 |
|---|---|---|
| **G1** 契约冻结 | 数据字典 + 接口 + 5 项架构决策签字 | PM + Arch |
| **G2** 模块交付 | 单模块按 05 模板自测通过（完整文件+运行+测试+验收） | 对应实现人 + QA 抽检 |
| **G3** 端到端跑通 | 40 回合可推进 + 存档往返 + 随机复现 + 版本拒绝 | A(集成) + Arch |
| **G4** 交付 | npm test 全绿 + 浏览器手测清单通过 + Pages 预览可达 | QA + 主理人 |

## 3. 协作规范（铁律）

1. **契约优先**：实现任一模块前必须先对齐 `docs/` 下的数据字典与接口；接口变更需全员确认并回填文档（禁止静默改契约）。
2. **文件交接协议**（无 git 后端时）：模块产出落到约定路径，依赖方只读契约文件 + `docs/`；模块间通过统一**结果对象 `{ok, state?, data?, message?, reason?}`** 通信，不靠口头约定。
3. **编码红线**（交接 01，违反即 Gate 不通过）：
   - 原生 ES2020 模块、无框架、无打包器、HTTP 运行（禁 `file://`）；
   - `core/events/config` 层**禁止**触碰 DOM / IndexedDB / LocalStorage；
   - 随机数唯一入口 `rng.js`；
   - 数值全**配置驱动**（`config/*.json` + `schema.js` 校验）；
   - 浏览器本地存储 + 存档导入导出。
4. **所有权边界**：core 独占写 `GameState`；UI 只通过 `callbacks` 提交、只读 `render(state)`；storage 由 `main` 协调，不被 core 直接调用。
5. **随机数复现**：`rngState` 序列化进存档；`core/events` 中**禁止出现 `Math.random`**。
6. **静态约束纳入冒烟**：`core/events` 无 `Math.random` / DOM / 存储引用，由 `tests/smoke.mjs` 自动检查。

## 4. 交付流程（每模块按 05 模板）

交接 05 规定的阶段任务模板，**每个模块交付物必须包含**：

1. **完整文件**（含绝对/相对路径与关键代码片段说明）
2. **运行方法**（如何启动、依赖）
3. **测试方法**（如何自测、断言）
4. **验收结果**（PASS/FAIL + 证据，如测试输出截图/日志）

禁止「半成品提交」：未自测通过的不进入 G2 合入。

---

## 5. 质量关卡

- **架构一致性审查**：工程师完成一批次后做全局一致性审查，输出 `IS_PASS: YES/NO`（跨文件契约一致性、红线合规）。`NO` → 修复后重审（最多 2 轮）。
- **QA 智能路由**：源码 Bug → 回工程师修复（附错误信息与失败测试）；测试代码 Bug → QA 自修；全过 → 报告成功。最多 2 轮；2 轮仍不过则标注遗留问题。
- **冒烟门槛**：`npm test` 必须全绿（配置校验 / 规模下限 / 存档往返 / 静态约束）才允许进入 G3/G4。

## 6. 定义完成（DoD）

- **功能**：40 回合可玩、6 结局可达、存档 / 图鉴 / 导入导出可用。
- **质量**：`npm test` 全绿、浏览器手测清单通过、`core` 无违规引用。
- **部署**：Pages 预览可达、相对路径、HTTPS。
- **文档**：`docs/` 同步更新、`README` 含运行/部署步骤。

## 7. 本 AI 辅助会话中的执行方式

主理人协调顺序：**PM 澄清歧义 → Arch 任务分解 → Eng 实现 → QA 测试**。各角色结论经主理人中转，不互相直连。

当前状态：PRD/架构已在阶段0冻结（见 `docs/开发方案.md`、`DATA_DICTIONARY.md`、`INTERFACES.md` 与配置骨架），故直接进入 **Arch 任务分解 → Eng 实现 → QA 测试**。真实四人按 A/B/C/D 归属领取任务，AI 会话中的 Eng/QA agent 按相同契约产出可执行代码与测试。
